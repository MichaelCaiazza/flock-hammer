# Architecture

Flock Hammer has two moving parts: a static front end served to browsers, and a
scheduled Node script that regenerates the data the front end reads. They meet
only through files committed in the `data/` folder.

## Front end

Two standalone HTML files, each containing its own CSS in a `<style>` block and
its own JavaScript in an inline IIFE. There is no shared script file, no bundler,
and no framework. `index.html` is the interactive map; `stats.html` is a
read-only dashboard. A web app manifest (`manifest.webmanifest`) and a service
worker (`sw.js`) make the site installable as a Progressive Web App.

`index.html` loads camera data from `data/cameras.json`. If that file is missing
(for example before the first nightly run), it falls back to querying the
Overpass API live from the browser. It renders cameras as clustered circle
markers, switches to a heatmap when zoomed out past zoom 8, and draws view-angle
"cones" at zoom 13 and closer. It reads and writes the URL hash to make map
position and a selected camera shareable, and it calls the Nominatim API for
location search.

`stats.html` loads `data/cameras.json`, `data/history.json`, and `data/new.json`
and renders totals, deltas, a growth line chart (inline SVG), ranked bar lists,
a vendor breakdown, and a recently-added list. It never queries Overpass.

## Back end

There is no application server. The only server-side component is
`scripts/export.mjs`, run by GitHub Actions on a schedule (and on manual
dispatch). It queries Overpass in regional slices, tags each camera with a US
state via point-in-polygon against downloaded state outlines, writes the four
`data/` files, and commits them with `git push` back to the repository.

## Where state lives

- **Durable data:** the committed files under `data/` in the repo. These are the
  single source the pages read at runtime.
- **Map/session state:** held in JavaScript variables in `index.html` (the
  `cameras` array, a `markers` Map) plus the URL hash (`#map=zoom/lat/lon&cam=id`)
  for position and selected camera. Filter toggles are read from the checkbox
  elements directly.
- **Offline/PWA cache:** the Cache Storage entry `flock-hammer-v1`, managed by
  `sw.js`.
- **Upstream source of truth:** OpenStreetMap. All camera facts originate there;
  the repo's `data/` files are a nightly snapshot.

## Repo map

```
/
├── index.html                     Map page: UI, styles, and map logic inline
├── stats.html                     Stats dashboard: UI, styles, and logic inline
├── README.md                      Short repo overview and deploy steps (pre-existing)
├── manifest.webmanifest           PWA manifest (name, icons, standalone display)
├── sw.js                          Service worker: core-file cache, PWA install support
├── scripts/
│   └── export.mjs                 Nightly data generator (Overpass → data/ files)
├── assets/
│   ├── logo.svg                   App icon: dark square with orange sweep (favicon)
│   ├── icon-32.png                32px PNG favicon
│   ├── icon-180.png               180px Apple touch icon
│   ├── icon-192.png               192px PWA icon (purpose "any")
│   ├── icon-512.png               512px PWA icon (purpose "any")
│   └── icon-maskable-512.png      512px PWA icon (purpose "maskable", padded)
├── .github/
│   └── workflows/
│       └── nightly.yml            Scheduled workflow that runs export.mjs and commits data/
└── data/                          Generated by the workflow; not in source control until first run
    ├── cameras.json               Compact snapshot of all cameras (read by both pages)
    ├── history.json               One totals entry per day (growth chart)
    ├── new.json                   Recently added cameras (new layer, recently-added list)
    └── feed.xml                   RSS feed of newly mapped cameras
```
