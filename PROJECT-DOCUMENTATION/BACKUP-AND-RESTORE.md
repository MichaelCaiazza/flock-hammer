# Backup and restore

## Where the data lives

All persistent data is the set of files under `data/` in the repository:
`cameras.json`, `history.json`, `new.json`, and `feed.xml`. They are committed to
git by the nightly workflow, so the repository (and its git history) is itself the
backup: every nightly commit is a restore point, and any past snapshot can be
recovered with normal git operations.

The upstream source of all camera facts is OpenStreetMap. Even without any local
backup, `data/cameras.json`, `history.json` (from that day forward), and
`new.json` can be regenerated by running `node scripts/export.mjs`. Note that
`history.json` and `new.json` accumulate over time, so regenerating from scratch
starts their history over; only the committed copies preserve past days.

## User-facing export (from the map)

The map's **Download area** tool exports the cameras currently in view (honoring
the active filters) as a file you can keep:

- **GPX** — for OsmAnd, Garmin devices, and most navigation apps.
- **KML** — for Google Earth and Google My Maps.
- **GeoJSON** — for developers and GIS tools.

This is a per-view export of camera points, not a backup of the whole dataset or
of the history/feed files.

## Restore

- **Restore a data file to a previous state:** check out or revert the file from
  an earlier commit in git history (e.g. a specific `Nightly camera data <date>`
  commit).
- **Rebuild current data from source:** run `node scripts/export.mjs`, or trigger
  the "Nightly camera export" workflow, which fetches from OpenStreetMap and
  rewrites the `data/` files. The script refuses to overwrite with fewer than 100
  cameras, protecting existing data against a failed fetch.

There is no separate database to back up or restore.
