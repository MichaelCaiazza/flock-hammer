# Data model

Flock Hammer has no database. Its data is four files under `data/`, generated by
`scripts/export.mjs` and read by the pages. Camera facts originate as tags on
OpenStreetMap nodes.

## Source records: OpenStreetMap nodes

The export selects OSM nodes matching either of:

- `man_made=surveillance` and `surveillance:type=ALPR`
- `man_made=surveillance` and `manufacturer` matching `flock` (case-insensitive)

Each node has an OSM node `id`, a `lat`/`lon`, a last-edited `timestamp` (from
Overpass `out meta`), and a set of tags. Only these tags are carried into
`data/cameras.json` (constant `KEEP_TAGS`):

`manufacturer`, `operator`, `direction`, `camera:direction`, `camera:mount`,
`surveillance:zone`, `start_date`, `note`, `website`, `contact:website`,
`operator:website`.

A camera is treated as a Flock camera when its `manufacturer` tag matches
`flock` (case-insensitive). Each camera is also tagged at export time with the US
state it falls in, computed by point-in-polygon against downloaded state
outlines; cameras outside those outlines get a null state.

## `data/cameras.json` — full snapshot (read by both pages)

A compact, de-duplicated encoding designed to keep the file small. Shape:

```
{
  "generated": "<ISO 8601 timestamp>",
  "source": "OpenStreetMap contributors, via Overpass API",
  "strings": [ "<string>", ... ],
  "cameras": [
    [ id, lat, lon, tsDays, stateIdx, [ kIdx, vIdx, kIdx, vIdx, ... ] ],
    ...
  ]
}
```

- `strings` is a shared string table. All tag keys, tag values, and state names
  are stored once here and referenced by index elsewhere.
- Each camera is an array: OSM node `id`; `lat` and `lon` rounded to 5 decimal
  places; `tsDays` = whole days since the Unix epoch of the node's last edit
  (`0` = unknown); `stateIdx` = index into `strings` for the state name, or `-1`;
  and a flat list of alternating key/value indices into `strings` for the kept
  tags.
- Both `index.html` and `stats.html` decode this by rebuilding each camera's
  `tags` object from the string table. `index.html` converts `tsDays` back to a
  millisecond timestamp for the "new" test.

## `data/history.json` — daily totals (growth chart)

An array with one entry per day; the export replaces any existing entry for the
current date:

```
[ { "date": "YYYY-MM-DD", "total": <number>, "flock": <number> }, ... ]
```

`stats.html` uses the last entry for current totals and looks back 7 and 30 days
to compute deltas and to draw the growth line.

## `data/new.json` — recently added (new layer / recently-added list)

An array of cameras first seen by the diff, most recent first, capped at 2000
entries and pruned to the last 90 days (`NEW_KEEP_DAYS`):

```
[ {
  "id": <osm node id>, "lat": <number>, "lon": <number>,
  "state": <string|null>, "flock": <boolean>,
  "operator": <string|null>, "manufacturer": <string|null>,
  "seen": "<ISO 8601 timestamp>"
}, ... ]
```

"New" is determined by diffing the current camera ids against the previous
`data/cameras.json`. On the first run (no previous file, or a previous file that
was empty), nothing is flagged as new, to avoid marking the entire dataset.

## `data/feed.xml` — RSS feed of new cameras

A standard RSS 2.0 document built from `data/new.json` (up to 200 items). Each
item's `guid` is `osm-node-<id>`; its link is a deep link into the map
(`<SITE_URL>/#map=17/<lat>/<lon>&cam=<id>`) when `SITE_URL` is set.

## `data/cameras.geojson` — legacy, removed

An earlier full-GeoJSON snapshot. The export deletes it if present. It is not
read by the current pages.

## IDs and timestamps

- **IDs:** cameras are identified by their OpenStreetMap node id throughout
  (data files, deep links, the RSS `guid`, and "Edit on OSM" links).
- **Timestamps:** `generated` in `cameras.json` and `seen` in `new.json` are full
  ISO 8601; `history.json` uses `YYYY-MM-DD` dates; `cameras.json` per-camera
  time is stored as whole days since epoch.

## Sync, export, backup

Data is regenerated wholesale each night from OpenStreetMap and committed to git,
so the repository's git history is the record of past snapshots. User-facing
export of the currently viewed cameras (GPX, KML, GeoJSON) is available from the
map; see `USER-GUIDE.md` and `BACKUP-AND-RESTORE.md`.
